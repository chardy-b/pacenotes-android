# WIL-102 — independent verifier/integrator lane

**Linear:** [WIL-102](https://linear.app/wildhearts/issue/WIL-102/p1-add-independent-verifierintegrator-lane)

## Outcome

Factory work has separate implementation and independent verification/integration lanes. The verifier checks the exact PR head against the packet, gate matrix, integration impact, and structured acceptance rows before Richard decides. No lane may merge or release.

### Inputs and outputs

- **Inputs:** Linear ticket/state; `docs/factory/<WIL-ID>.md`; exact 40-character PR-head SHA; baseline CI; API-35 device artifacts when applicable; screenshots/recordings and UI XML/accessibility artifacts for frontend/major PRs; and integration context.
- **Outputs:** `PASS`, `FINDINGS`, or `BLOCKED`, with evidence links; material finding severity; and a fix-or-defer record naming owner, rationale, and follow-up.
- **Escalation:** missing, stale, failed, cancelled, skipped, or unreviewed mandatory evidence is `NO-GO/BLOCKED`; unresolved risk is escalated to Richard in Linear.

## Deterministic review gates

Baseline-only work always requires exact-head baseline CI. Device evidence is mandatory for UI/Compose, permissions, location/GPS replay, foreground service, audio/TTS, MapLibre/rendering, lifecycle, and any Android runtime-specific behavior; it must include API-35 automated/device/visual conclusions. Release is considered only when the user explicitly requests it after reviewed successful device evidence and the artifact is unchanged. Release includes baseline/device evidence as applicable. Any absent or non-matching evidence blocks the decision.

## Terra UX review protocol

For every frontend-facing change or major PR, the assigned verifier/integrator or controller posts a Terra review request as a Linear comment on the ticket before dispatching/assigning the independent Terra reviewer. The request must contain the ticket URL, PR URL, exact 40-character head SHA, packet path, evidence links, review scope/checklist, and requested outcome. The Linear comment and assigned reviewer are the handoff; there is no Terra CLI or automatic dispatch. Record the request comment URL and final report URL in both the packet and PR, alongside exact head, evidence links, and one outcome: `PASS`, `FINDINGS`, or `BLOCKED`. `FINDINGS` requires fix/defer and Terra re-review on the exact new head; `BLOCKED` escalates to Richard. Missing required visual evidence is `BLOCKED` for the final decision. Terra is non-approving and non-merging and never replaces CI, device, verifier, artifact, or human gates.

## Independence attestation

Each review records implementer and verifier identities and roles, confirms they are separate for the required review, and records attestation `PASS` or `FAIL`. A failed or absent attestation is `BLOCKED`.

The lane is recorded in each packet and in one run entry per actual run at `docs/factory/runs/<WIL-ID>/<RUN-ID>.md`; create it plus the per-ticket `docs/factory/runs/<WIL-ID>/INDEX.md` row from [`RUN-LEDGER-TEMPLATE.md`](RUN-LEDGER-TEMPLATE.md) only for an actual run. Use the exact `YYYYMMDDTHHMMSSZ-<short-head>-NN` format and index algorithm in [`README.md`](README.md). See [`CONTRACT-TEMPLATE.md`](CONTRACT-TEMPLATE.md).
