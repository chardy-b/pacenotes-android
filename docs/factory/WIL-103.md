# WIL-103 — factory run ledger

**Linear:** [WIL-103](https://linear.app/wildhearts/issue/WIL-103/p2-add-per-ticket-factory-run-ledger)

## Outcome and destination

Each actual factory run has exactly one entry at `docs/factory/runs/<WIL-ID>/<RUN-ID>.md`, created from [`RUN-LEDGER-TEMPLATE.md`](RUN-LEDGER-TEMPLATE.md), and one row in `docs/factory/runs/<WIL-ID>/INDEX.md`. README links only to per-ticket indexes. `RUN-ID` is exactly `YYYYMMDDTHHMMSSZ-<short-head>-NN`, with `NN` two-digit zero-padded from `01`. Before creating a record, read the index; for the same exact `started_utc` second and exact head choose one greater than the largest existing `NN`; create record and row together in one PR/commit. Review/CI statically checks uniqueness. Concurrent same-ID branches are resolved by the later-to-merge branch rebasing, re-reading, allocating the next `NN`, and updating filename and row before merge; no locking is claimed. Do not create fake or placeholder entries. The packet remains `docs/factory/<WIL-ID>.md`; Linear remains lifecycle authority.

## Normalized schema

Every entry uses these machine-comparable fields and allowed values:

- `quality_outcome`: `pass | findings | blocked`.
- `max_finding_severity`: `none | low | medium | high | critical` (use `none` when there are no findings).
- `evidence_requested`: required list of evidence items. Each item has exactly these explicit fields: `name`, `required`, `disposition`, `exact_head_sha`, `reference`, and `rationale`.
- `evidence disposition`: `supplied | missing | stale | not-applicable | rejected`. `not-applicable` requires a written rationale; `missing`, `stale`, and `rejected` cannot support GO.
- `evidence_completeness`: `complete | partial | missing`, derived objectively from dispositions for all mandatory items.
- `rework_requested`: `yes | no`; `rework_completed`: `yes | no | not-applicable` with evidence when `yes`.
- `elapsed_time_utc`: `start`, `end`, and ISO-8601 duration; unknown values are absent, never fabricated.
- `final_decision`: `GO | NO-GO | BLOCKED | DEFERRED` (Richard's Linear decision/link required).
- `deferral`: `state` `not-deferred | deferred`, plus `rationale`, `owner`, and `follow-up`; absent fields are `null`, while N/A is the literal `not-applicable` only where allowed.
- `independence_attestation`: implementer identity/role, verifier identity/role, and `PASS | FAIL`; absent attestation is `FAIL/BLOCKED`.

Exact-head identity is mandatory on the entry and on every supplied/stale/rejected evidence item. No invented metrics: comparison uses only populated fields.

## Up-to-five comparison schema

A comparison contains 1–5 actual entries and only these columns: `wil_id`, `quality_outcome`, `max_finding_severity`, `evidence_completeness`, `rework_requested`, `rework_completed`, `elapsed_time_utc`, and `final_decision`. If a source value is absent, serialize `null`; do not turn absence into zero, success, or N/A. Never invent aggregate metrics.

The ledger records evidence, not authority. It contains no secrets or unnecessary personal data and does not replace Linear or GitHub.
