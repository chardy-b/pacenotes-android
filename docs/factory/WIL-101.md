# WIL-101 — factory contract and evidence packet schema

**Linear:** [WIL-101](https://linear.app/wildhearts/issue/WIL-101/p0-add-factory-contract-and-evidence-packet-schema)

## Outcome

The canonical contract/evidence packet is `docs/factory/<WIL-ID>.md`. Each actual run has exactly one ledger entry at `docs/factory/runs/<WIL-ID>/<RUN-ID>.md`, created from [`RUN-LEDGER-TEMPLATE.md`](RUN-LEDGER-TEMPLATE.md) and indexed by `docs/factory/runs/<WIL-ID>/INDEX.md`; the repository README links only to that per-ticket index. `RUN-ID` is exactly `YYYYMMDDTHHMMSSZ-<short-head>-NN`, with `NN` two-digit zero-padded from `01`. Before creating a record, read the index and, for the same exact `started_utc` second and exact head, choose one greater than the largest existing `NN`. Create record and row together in one PR/commit; review/CI statically checks uniqueness. A concurrent same-ID allocation is resolved by the later-to-merge branch rebasing, re-reading the index, allocating the next `NN`, and updating both filename and row before merge. No locking is claimed. Do not create an entry for a run that did not occur.

Packets define inputs, bounded scope and non-goals, acceptance criteria, risk classification, exact-head evidence, independent review, and a human decision. Linear remains authoritative for lifecycle, ownership, approval, and risk acceptance.

## Deterministic gate matrix

| Work characteristic | Mandatory gate | Required conclusion |
|---|---|---|
| Baseline-only documentation/process change | Exact-head baseline CI | Passing baseline CI on the exact 40-character head SHA |
| UI/Compose, permissions, location/GPS replay, foreground service, audio/TTS, MapLibre/rendering, lifecycle, or any Android runtime-specific behavior | Baseline CI **and** API-35 device gate | Automated, device, and visual conclusions, all tied to the exact head and API-35 artifacts |
| Release requested explicitly by the user | Applicable baseline/device gates, then reviewed unchanged release artifact | Release is considered only after successful reviewed evidence; no implicit release request |

A missing, stale, failed, cancelled, skipped, or unreviewed mandatory artifact is `NO-GO/BLOCKED`. Release evidence includes baseline/device evidence when applicable. Evidence from another SHA never satisfies a gate.

## Terra UX review

For every frontend-facing change or major PR, the assigned verifier/integrator or controller posts a Terra review request as a Linear comment on the ticket before dispatching/assigning the independent Terra reviewer. Required fields are ticket URL, PR URL, exact 40-character head SHA, packet path, evidence links, review scope/checklist, and requested outcome. The Linear comment and assigned reviewer are the handoff; no Terra CLI or automatic dispatch is implied. Record the request comment URL and final report URL in the packet and PR. Terra reports evidence links plus exactly `PASS`, `FINDINGS`, or `BLOCKED`; `FINDINGS` requires fix/defer and re-review on the exact new head; `BLOCKED` escalates to Richard. Missing required visual evidence is `BLOCKED` for the final decision. Terra never merges, approves, or replaces baseline CI, device, verifier, artifact, or human gates.
